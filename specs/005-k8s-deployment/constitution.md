# Constitution: AI-Driven Kubernetes Deployment

## Core Principles

### 1. Agent-Driven Execution Mandate
- All infrastructure artifacts must be generated by AI-powered CLI tools
- Manual creation of Dockerfiles, Kubernetes YAML, or Helm templates is strictly prohibited
- Human role is limited to orchestrating AI agents and validating outcomes

### 2. Real System State Changes
- All workflow steps must produce tangible execution outcomes (images, pods, services, Helm releases)
- No documentation-only or theoretical steps permitted
- Every action must result in measurable changes to system state

### 3. Locked Tooling Compliance
- Docker AI (Gordon) is the sole authorized containerization mechanism
- kubectl-ai is the exclusive Kubernetes deployment interface
- Helm is mandatory for application packaging
- Minikube is the required local Kubernetes runtime

### 4. No Manual Infrastructure Coding
- Zero tolerance for human-authored Dockerfiles
- Zero tolerance for human-authored Kubernetes YAML
- Zero tolerance for human-authored Helm templates
- All infrastructure code must originate from AI agents

### 5. No Optional Tools or Alternate Paths
- Only the specified AI tools (Gordon, kubectl-ai, Helm, Minikube) are permitted
- All paths must follow the locked tooling approach

## Enforcement Mechanisms

### Pre-Execution Validation
- Verify AI tools are installed and accessible before beginning
- Confirm Minikube cluster is available and running
- Validate that no manual infrastructure files exist in project
- Ensure no optional tools are included in the workflow

### Execution Monitoring
- Monitor for any manual file creation during process
- Track AI agent usage for compliance
- Log all system state changes for audit trail
- Verify that only locked tooling is used

### Quality Gates
- Block progression if manual infrastructure artifacts are detected
- Require AI-generated provenance for all artifacts
- Validate that all resources meet security and operational standards
- Confirm that no optional tools or alternate paths are used

## Failure Response Protocol
- If AI tools fail, document failure and seek alternative AI approaches
- Never fall back to manual infrastructure coding
- Never introduce optional tools not in the locked tooling
- Restart from validated checkpoint if manual artifacts are accidentally created
- Report tool limitations to improve AI agent capabilities

## Success Definition
- Complete deployment achieved using only AI-generated artifacts
- All system components running in Kubernetes cluster
- Helm chart successfully managing the application
- No manual infrastructure files present in final state
- No optional tools or alternate paths used in the workflow
- All steps produce real execution outcomes (images, pods, services, Helm releases)
